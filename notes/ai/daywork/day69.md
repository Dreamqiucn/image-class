# Day 69：保存、加载模型并单独预测

## 今天的目标

在 Day 68 的 CNN 训练结束后保存模型参数，再由一个独立运行的预测入口加载参数，对一张练习图片输出分类结果。预测时不重新训练。当前只是用极少量样本检查工作流程，不能判断模型是否具备可靠的动漫人物识别能力。

## 三个新用法

```python
# 训练结束后保存当前模型参数
torch.save(layers.state_dict(), "output/day69_weights.pth")

# 预测时先创建相同结构的新模型，再读取参数
weights = torch.load("output/day69_weights.pth", map_location="cpu", weights_only=True)
new_model.load_state_dict(weights)
new_model.eval()
```

此片段不完整，layers 和 new_model 需要先创建；没有 print，不产生终端输出。state_dict 是模型参数及持久缓冲区组成的字典，不包含完整网络定义。因此新模型必须具有与原模型相同的结构、各层顺序和参数尺寸。

torch.load 读取文件得到参数字典，load_state_dict 接收的是字典，不是文件路径。map_location="cpu" 让预测在 CPU 加载，便于 Mac 和 Windows 间使用；weights_only=True 用于加载这种权重字典。eval 切换模型模式，with torch.no_grad() 关闭预测过程的梯度记录，两者用途不同。

这些参数文件只够今天做推理练习；要完整恢复训练过程还可能需要优化器、训练轮次等信息，今天不要求实现。

## 自己实践

1. 沿用 Day 68 的结构和训练流程，训练后把 layers.state_dict() 保存为 output/day69_weights.pth；先确保 output 目录存在。保存同名文件会覆盖旧文件。
2. 新建独立预测脚本，重新定义与 Day 68 相同的网络结构，使用 torch.load 和 load_state_dict 加载权重。不要导入会在模块顶层自动执行 day68() 的脚本，否则会触发训练；模型结构今天可以先重复定义，后续再整理复用。
3. 选择一张练习图片，推理时沿用验证预处理：Pillow 转 RGB、resize((64,64))、转 NumPy/Tensor、调整为 (C,H,W)、除以 255.0，不做随机翻转；加一个 batch 轴，成为 (1,3,64,64)。模型、输入都在 CPU 上。
4. 设置 eval，在 no_grad 中前向计算，打印图片路径、logits 和预测类别编号。可使用本次训练映射 0=丰川祥子、1=汐见萤显示名称，但该映射只用于当前练习，不是已确定的正式类别表。
5. 单独运行预测脚本，确认它不启动训练，且能从磁盘读取权重并给出结果。为确认权重真的加载，可在训练结束保存前对同一输入进行 eval/no_grad 预测，和新模型加载后的 logits 使用 torch.allclose 对比；输入预处理和模型模式保持相同，允许浮点误差。

本次不要求做图形界面、计算准确率、保存优化器、寻找最佳轮次或准备正式数据集。仅使用自有的练习权重进行加载。

## 验收

- 训练权重文件由实际训练的模型保存；独立预测进程可读取文件，且不会触发训练。
- 预测模型结构和输入形状匹配，预处理与验证一致，不做随机增强；预测输出至少包含图片与类别编号。
- 保存前与加载后的同一输入 logits 接近，或有等效证据验证保存与加载无误；预测类别正确与否不是唯一判据。
- 不把训练集或单张验证图片结果说成真实泛化能力。当前 .gitignore 排除 output/ 和 *.pth，权重不会自动进入 Git。
