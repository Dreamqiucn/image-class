## 本日问题与解释

### 1. SyntaxWarning: invalid escape sequence 是什么

用户在输出字符串中直接写 Windows 反斜杠路径，触发非法转义警告。反斜杠在普通 Python 字符串中用于转义，例如换行；不认识的组合会警告。建议用 Path 连接目录后转换或格式化打印，也可把字符串中的反斜杠写成双反斜杠。该警告通常不阻止本次程序继续执行，但应修正写法。

### 2. 不那样拼接，为什么路径出现反斜杠和斜杠混合

Windows 通常能识别混合分隔符，不代表路径本身无效。用 Path 对象统一拼接，再打印 resolve()，可以保持 Windows 本地显示格式；保存与打印最好使用同一个目标路径。路径末尾 samples 不会自动变成 samples.csv，扩展名需要明确包含在文件名中。用户最终打印 str(p.resolve() / "output/samples.csv")，该相对部分由 Path 解析，实际验证通过。

### 3. 输出成功消息末尾怎么换行

可在末尾加换行转义字符。print 默认就追加一次换行，再加一个会留一行空白。最终脚本有意在成功提示后留空行，不将其作为问题。

### 4. DictReader 读出来为什么是一串列表和字典

这是正常形状：外层 rows 是列表，每个 row 是一行字典，表头决定键名。可以逐行读取 row["path"] 与 row["label"]。用户最初写入表头 lable，因此读回键也是 lable；需要修改写入表头并重新导出，不能只改读取键。列表打印时路径中的双反斜杠是字符串表示中的转义，直接 print 单个路径时显示普通反斜杠，不代表路径实际有两个分隔符。

### 5. 最后要做成什么样

读取列表形状已经正确，下一步应从读回 rows 统计类别并打印：输出位置、读回图片数量 3，以及 {"cat": 2, "dog": 1}。数量用 len(rows)，类别以读回行中的 label 累加；不能重新扫描目录来代替文件读回核对。

### 6. list object has no attribute get，哪里错了

用户把 counts 初始化成 []，但 get 是字典方法。应初始化 counts = {}。同时原先 get([row["label"], 0]) 把列表当成一个参数，应写 get(row["label"], 0)，分别传键与默认值。字典中尚无类别时取 0，再加 1 保存。

### 7. 修改 get 后为什么没有变化

再次读取真实脚本发现 get 参数已改对，但 counts 仍在原第 21 行初始化成列表。指出只需把 counts = [] 改为 counts = {}，保存再运行。rows = list(reader) 保留，因为读取结果本来就是列表。最新代码已修正并加入列表、字典与行字段含义的注释。
