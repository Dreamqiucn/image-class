## 本日问题与解释

### 1. 逐张图片的 try/except 为什么放在循环里面

每一轮单独尝试打开和加载一张图片，遇到 OSError 时提示出错路径，再 continue 跳过本轮剩余语句。没有报错时跳过 except，才把样本加入有效列表。若整批循环都包在同一个 try 里，一张失败会离开该 try，后面图片不会自动继续。

### 2. try/except 能不能放在函数里

可以。函数内 for 循环中也可写 try/except，continue 跳过的是这轮 for，不是退出整个函数。单独定义的函数如果没有自己的循环，不能靠 continue 跳过调用者的外部循环。

### 3. photos_number += 1 为什么报 UnboundLocalError

该语句包含赋值，Python 将函数内的 photos_number 视为局部变量，但它还没有局部初始值。模块外层已初始化同名变量也不会自动作为这个局部变量。用户希望修改外部计数器时，在函数开头 global photos_number；也解释过可用返回的成功列表长度得到计数。

### 4. first 给 output_dir 赋值后为什么仍输出到项目根目录

first 原先只给局部 output_dir 赋值并创建目录，save 读取的却是全局 output_dir=Path('')，后者表示当前工作目录。first 增加 global output_dir 后，函数赋值才更新模块全局路径。global 只作用于明确声明的变量，不会使函数内所有赋值都变为全局赋值。

### 5. 外部能否给函数内部的变量赋值

外部不能通过同名变量直接修改函数的局部绑定。可以通过参数把值传入，通过 return 取回结果；也可明确使用模块全局变量，但那就不再是该函数的局部变量。没有将“无法直接修改局部变量”泛化为所有对象都无法共享修改。

### 6. return 为什么会在控制台输出

普通脚本中 return 本身不打印，只将结果返回调用者。result=func() 接收结果不会额外输出；print(func()) 才会主动打印。交互式解释器或 Notebook 可能展示表达式结果，赋给变量一般不会显示。
